# 微信小游戏开发版

这个目录是一套不依赖 AppID 的原生 Canvas 小游戏客户端。当前通过 `dev` 身份适配器连接现有 Next.js API；拿到微信小游戏账号后，保留 UI、棋盘、房间和数据层，只替换登录模式、AppID 与正式 HTTPS API 域名。

## 已完成

- `game.js` 微信小游戏入口和 `game.json`
- `touristappid` 开发项目配置
- 9 个稳定随机分配的像素头像
- 开发身份登录、昵称和用户档案
- 胜/负/和/总局统计与最近对局日期
- 创建房间、房间码加入、微信分享查询参数
- 双方昵称、头像、在线/离线状态
- 15×15 棋盘、轮次、最后一手与胜负状态
- 退出后从账号恢复未结束房间
- 按 `revision` 拒绝旧轮询，避免棋局回滚
- 浏览器 Canvas 预览与核心逻辑测试

## 无 AppID 运行

在仓库根目录：

```bash
npm ci
npm run dev
```

打开：

```text
http://127.0.0.1:3000/minigame-preview/index.html
```

浏览器预览使用本机 API，并在本地存储生成稳定的开发设备身份。使用无痕窗口可以模拟第二位用户。

## 微信开发者工具

安装微信开发者工具后，导入本目录 `minigame/`：

- 项目类型：小游戏
- AppID：当前配置为 `touristappid`
- 本地开发时关闭合法域名校验
- 本机 API：`http://127.0.0.1:3000`

没有正式 AppID 时，`wx.login`、真机微信转发和正式合法域名无法最终验收；浏览器预览会模拟这三处外壳，但使用同一套应用代码。

## 拿到账号后的配置

1. 把 `project.config.json` 的 `appid` 替换为正式小游戏 AppID。
2. 把 `src/config.js` 的 `API_BASE` 替换为备案后的 HTTPS 域名或微信云托管入口。
3. 在服务端新增微信 code-to-session 交换，并把 `POST /api/auth/session` 从 `mode: dev` 切换为 `mode: wx`。
4. AppSecret 只保存在云环境变量，绝不写入小游戏或 Git。
5. 在开发者工具和两台真机上复验登录、分享卡片、后台切回、弱网和在线状态。
6. 生产环境保持 `ALLOW_DEV_AUTH` 关闭。
